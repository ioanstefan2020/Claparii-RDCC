## Feature: Employer Web UI (T3.5 — F6)

### Goal
Provide an accessible web interface (WCAG 2.2 AA compliant, passing `tests/test_a11y_static.py`) allowing HR staff and employers to audit workplace documents (onboarding guides, job ads, internal policies) for cognitive accessibility, view readability metrics, review detected clarity issues with verbatim quotes, copy/download easy-read rewrites, and discover recommended workplace adjustments.

### Non-goals
- Scoring or evaluating candidates/employees (strict responsible-AI boundary: score documents only).
- Storing employer documents on the server.
- Parsing binary `.docx`/`.pdf` formats directly (text paste and `.txt` upload only).
- Modifying `web/shared/api.js` (owned by P2) — `employer.js` handles API requests and fallback directly.

### Design
- **Architecture**: Single-page vanilla ES module interface conforming to repo conventions (`web/shared/a11y.css`, `web/shared/profile.js`).
- **File layout**:
  - `web/employer/index.html`: Semantic HTML5 structure with skip link, single `<h1>`, `<main id="main">`, `<form id="employer-form">`, `#status-live` live region, and result cards.
  - `web/employer/employer.js`: ES module handling form submission, file upload reading, sample loading, API calls to `POST /api/employer/analyze`, offline/mock fixture fallback (`?mock=1`), visual card rendering, focus management (`results-heading.focus()`), copy-to-clipboard, text download, and Web Speech TTS.
  - `web/employer/fixture.json`: Canned mock response matching CONTRACTS §3.6 for offline use and `?mock=1`.
  - `web/i18n/ro.employer.json`: Romanian copy strings, semantic badge mappings, readability score classifications, and screen reader announcement templates.

### Interfaces & Contracts
- **Endpoint**: `POST /api/employer/analyze` (CONTRACTS §3.6)
  - Request: `{"text": string (1..12000 chars), "doc_type": "onboarding" | "job_ad" | "policy" | "other"}`
  - Response: `{"ok": true, "data": {"readability": {"sentence_count": int, "avg_sentence_words": float, "long_sentences": [{"text": str, "words": int}], "score_0_100": int}, "issues": [{"kind": str, "quote": str, "fix": str}], "easy_read_ro": str, "adjustment_checklist": [{"id": str, "title": str}]}, "meta": {"provider": str, "cached": bool, "warnings": list[str], "ai_notice_ro": str}}`
- **Readability score semantic thresholds**:
  - `80 - 100`: "Accesibilitate excelentă" (green `.status-success`)
  - `50 - 79`: "Accesibilitate moderată — recomandăm simplificări" (amber `.status-warning`)
  - `0 - 49`: "Accesibilitate dificilă — fraze prea dense sau lungi" (red `.status-error`)
- **Issue kind label mapping**:
  - `jargon`: "Jargon corporatist"
  - `long_sentence`: "Frază prea lungă"
  - `missing_deadline`: "Termen lipsă"
  - `vague_instruction`: "Instrucțiune vagă"
  - `missing_structure`: "Structură deficitară"

## Feature: End-to-End Smoke Test Suite (T3.6)

### Goal
Provide a comprehensive, automated end-to-end smoke test suite (`scripts/smoke.sh` and `tests/test_smoke.py`) that exercises all API endpoints with sample payloads, verifies envelope shapes and responsible AI guardrails, checks every web page for HTTP 200 and accessibility markup, and integrates into `./scripts/check.sh`.

### Non-goals
- Invoking live commercial LLM APIs during automated gates (smoke test uses `LLM_PROVIDER=mock` for deterministic, zero-cost, sub-5-second execution).
- Browser GUI automation with Selenium/Playwright (hackathon offline stack: fast HTTP & ASGI testing).

### Design
- **Shell Runner (`scripts/smoke.sh`)**:
  - Ephemeral port selection via `python3 -c "import socket; ..."` to prevent port collision.
  - Background uvicorn process management with `LLM_PROVIDER=mock`.
  - Trap handler on `EXIT INT TERM` guaranteeing clean shutdown (`kill -TERM $SERVER_PID`).
  - Active health check polling (`/api/health`) before sending test traffic.
  - Realistic `curl` requests with sample payloads:
    * `GET /api/health`
    * `POST /api/simplify` (with `data/samples/onboarding_ro.txt`)
    * `POST /api/plan/extract` (with `data/samples/task_email_ro.txt`)
    * `POST /api/meeting/summarize` (conditional check if mounted)
    * `GET /api/adjustments/catalog`
    * `POST /api/adjustments/draft` (with `["written_instructions", "extra_time"]`)
    * `POST /api/employer/analyze` (with `data/samples/onboarding_ro.txt`)
  - Verification of static HTML routes: `/`, `/index.html`, `/employee/profile.html`, `/employer/index.html`.
  - Negative error envelope check: `POST /api/employer/analyze` with empty input returns 400 + `{"ok": false, "error": {"code": "empty_input"}}`.
- **Pytest Suite (`tests/test_smoke.py`)**:
  - In-process ASGI test using `fastapi.testclient.TestClient(app)` so `scripts/check.sh` executes it on every run.
  - Validates exact envelope structure (`ok`, `data`, `meta.provider == 'mock'`, `meta.ai_notice_ro`).
  - Scans `web/` directory and asserts that every `.html` page is served with HTTP 200.
