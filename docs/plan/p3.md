## Feature: Adjustments API (T3.3)

### Goal
Provide accessible, responsible backend endpoints for functional workplace adjustments:
1. `GET /api/adjustments/catalog` serving the curated 12-item adjustments catalog in Romanian with legal/practice sources.
2. `POST /api/adjustments/draft` generating structured, professional accommodation request letters tailored by context and tone without disclosing or inferring medical diagnoses.

### Non-goals
- Medical diagnoses, clinical symptom logging, health profiling, or disability labeling.
- Free-text input of unverified adjustment requests or prompt-injection avenues in request payload (only catalog IDs accepted).
- Legal advice generation (all outputs state non-legal advisory nature).
- Frontend UI rendering (owned by P2 in T2.6).

### Design & Data Flow
- `GET /api/adjustments/catalog`: Reads & caches `data/adjustments_ro.json`, returns `CatalogEnvelope` per CONTRACTS §3.4.
- `POST /api/adjustments/draft`:
  1. Validates payload via `DraftRequest` (`extra='forbid'`, `need_ids` non-empty, all IDs exist in catalog).
  2. Builds Romanian prompts via `app/prompts/adjustments.py`.
  3. Invokes `generate_json` from `app.llm`.
  4. Applies responsible-AI deny-list guardrail: asserts no diagnostic terms in generated output.
  5. Returns `SuccessEnvelope[AdjustmentDraftData]` per CONTRACTS §3.5.
