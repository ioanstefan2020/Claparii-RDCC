## Feature: Stretch S2 /api/tone/suggest

**Goal:** Implement `POST /api/tone/suggest` providing text-only message suggestions (e.g. for asking a manager for clarification or requesting follow-up) with explicit stated uncertainty, no emotion/sentiment claims about the recipient, and respectful Romanian wording.
**Non-goals:** Emotion detection or facial/vocal sentiment analysis (strictly banned under EU AI Act).
**Design:**

- `app/schemas/tone.py`: `ToneSuggestRequest` (`text`, `context`, `profile`), `ToneSuggestData` (`suggestion`, `alternative_phrasings`, `uncertainty_notice_ro`).
- `app/prompts/tone.py`: SYSTEM prompt emphasizing stated uncertainty, polite plain-Romanian rephrasing, no emotional inference, and offline `MOCK`.
- `app/routers/tone.py`: Endpoint `POST /api/tone/suggest` auto-discovered at `/api/tone/suggest`.
- `tests/backend/test_tone.py`: Contract and bounds test.
  **Tasks:**
- [x] T1 (owns: `app/schemas/tone.py`) — Define Pydantic request and response schemas.
- [x] T2 (owns: `app/prompts/tone.py`) — Write prompt and mock payload.
- [x] T3 (owns: `app/routers/tone.py`) — Implement endpoint with input validation and error envelope.
- [x] T4 (owns: `tests/backend/test_tone.py`) — Unit test the endpoint.
      **Acceptance criteria:**

1. Tests pass: `python3 -m pytest tests/backend/test_tone.py`.
2. Gate passes: `./scripts/check.sh` exits 0.
3. Server curl: `curl -X POST http://127.0.0.1:8000/api/tone/suggest` returns valid envelope with stated uncertainty.
